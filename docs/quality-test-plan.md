# 実機確認と画面確認の手順（仕様第13章）

**ブラウザーのエミュレーションだけで実機合格とはしません。**
端末が用意できない項目は「未確認」として残します。

自動試験（pytest / Playwright）で確認している範囲は本書の最後にまとめています。

---

## 1. 実機確認（ユーザーが行う）

### 1.1 前提

- `deploy/README.md` の手順で限定公開環境（VPS＋Caddy、HTTPS）を配置していること
- 実機からその FQDN に到達できること（IP制限を使う場合は、端末の回線が許可元に入っていること）
- 講師のアカウントが作られていること

**ローカル（127.0.0.1）では実機確認できません。** model-viewer の表示にHTTPSが要るためです。

| --- | --- | --- | --- | --- |
| iPhone Safari | | | | 未確認 |
| Android Chrome | | | | 未確認 |

### 1.3 チェックリスト

同じ表を端末ごとに使ってください。1つでも「いいえ」があれば、その端末は未合格です。

#### ログインと基本表示

- [ ] 前段の認証（IP制限またはBasic認証）を通らないと何も見えない
- [ ] ログイン画面の文字が読める（本文16px以上の想定）
- [ ] ログインでき、検証セット一覧が出る
- [ ] ボタンが指で押せる（44px以上の想定。押し間違いが起きない）
- [ ] 横スクロールが必要な箇所が、表以外に無い

#### 画像の登録

- [ ] 「ファイルを選ぶ」から写真アプリの画像を選べる
- [ ] 大きすぎる画像を選んだとき、日本語で理由が出る
- [ ] 登録した画像が縦横正しく表示される（横向きで撮った写真も含む）

#### 3D表示（最重要）

- [ ] 生成結果の画面でモデルが表示される
- [ ] 指で回せる。拡大・縮小ができる
- [ ] 「正面」「横」「背面」「真上」で視点が変わる
- [ ] 「表示をリセット」で戻る
- [ ] 背景色の切替が効く
- [ ] ページを縦にスクロールしても、モデルの上で指が引っかかって進まないことがない
- [ ] 読み込みに時間がかかるとき、その旨が表示される（無言のまま止まらない）
- [ ] 読み込みに失敗したとき、日本語のメッセージが出て、ボタンは押せるままである

#### 品質比較（2社）

- [ ] 縦並びになり、モデルが1つずつ切り替えて表示される
- [ ] 「A を表示」「B を表示」で切り替わる
- [ ] 評価が終わるまで、どちらのサービスかが**どこにも出ていない**
- [ ] 「いまの向きを『正面』にする」を押すと、その向きが基準になる

#### 評価の入力

- [ ] 5つの軸すべてを選べる
- [ ] 「実機で確認した」にチェックを入れないと、スマホの点数が未確認のままになる
- [ ] 重大不具合タグを複数選べる
- [ ] 送信後、評価が保存されたことがわかる

#### 通信が不安定なとき

- [ ] 機内モードにしてから操作しても、画面が壊れない
- [ ] 通信を戻すと、状態表示が追いつく

### 1.4 記録の残し方

確認できた項目・できなかった項目を、この表に日付と端末の版を入れて残してください。
**未確認の項目は空欄のままにし、推測で埋めないでください。**

## 2. 画面の自動確認（Playwright）

`tests/test_screens_playwright.py` で次を確認しています。実機確認の代わりにはなりません。

| 確認内容 | 対応する仕様 |
| --- | --- |
| 主要画面が表示でき、コンソールエラーが出ない | 第6章 |
| 3Dモデルが読み込まれ、視点操作のボタンが効く | 第6.5章 |
| ビューアーの読込失敗で、日本語のメッセージが出て操作不能にならない | 第13章 試験14 |
| ブラインド中の比較画面に、サービス名・モデルID・プリセット名が出ない | 第13章 試験18 |
| 評価確定後は開示され、サービス名が出る | 第13章 試験18 |
| スマホ幅で縦並びになり、ボタンが44px以上、本文が16px | 第6.6章 |

実行方法：

```bash
uv pip install playwright
.venv/bin/python -m pytest tests/test_screens_playwright.py -q
```

Playwright とブラウザーが無い環境では、これらの試験は自動的に飛ばされます。

## 3. 自動試験で確認している範囲（pytest）

仕様第13章の必須試験のうち、現在実施しているものです。

| 番号 | 内容 | 実施状況 |
| --- | --- | --- |
| 1 | 同じ冪等キーを連打しても依頼が1件 | 実施 |
| 2 | 2社比較の上限額が片方分しかなければ両方とも未送信 | 実施 |
| 3 | 同時受付でも上限額と送信枠を超過しない | 実施 |
| 4 | 作成応答タイムアウト後に自動で再POSTしない | 実施 |
| 5 | タスクID保存済みで再起動すると、同じタスクを再確認する | 実施 |
| 6 | submitting中に停止した場合は不明状態へ移り、人による照合が必要 | 実施 |
| 7 | 保存失敗は再取得だけを行い、課金生成を増やさない | 実施 |
| 8 | 2社の片方失敗でも他方の成果物と費用が残る | 実施 |
| 9 | 上限2回を画像加工・プリセット変更で回避できない | 実施 |
| 10 | 未認証の画像・GLB取得拒否、CSRF拒否、任意URL取得拒否 | 実施 |
| 11 | 外部URI参照GLB・偽拡張子画像・過大ファイルを拒否 | 実施（実アダプターの経路を含む） |
| 12 | モックと実API、未評価と合格、ブラインドと非ブラインド、早期確認と通常検証を集計で混同しない | 実施 |
| 13 | 費用確定イベントの重複でも二重計上されない | 実施 |
| 14 | ビューアーの読込失敗で操作不能・永久ローディングにならない | 実施（Playwright） |
| 15 | 合格0件・評価0件・生成0件で除算エラーにならない | 実施 |
| 16 | lease期限切れで submission_unknown へ移り、再submitしない | 実施 |
| 17 | provider_failedで枠返却、submission_unknownでは返却しない | 実施 |
| 18 | ブラインド中にサービス名等が漏れない。確定後は開示される | 実施（Playwright とAPIの両方） |
| 19 | 利用同意missingはAPI直叩きでも外部送信されない | 実施 |
| 20 | ダウンロード中でも他タスクの状態確認が同一ループ内で行われる | 実施 |

**実APIを使った試験は行っていません。** 自動試験は本番APIを呼びません。
